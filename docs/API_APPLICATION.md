# Заявка на доступ к API Яндекс Директа

## Технические данные о приложении

**Язык программирования:** Python 3.11+

**Протокол:** JSON (API v5)

**Назначение приложения:**
- Автоматизировать регулярную работу по управлению кампаниями в Директе
- Синхронизировать рекламно-информационные материалы с данными внутренних систем (товары, деньги, отчётность)

**Основные функции:**
- Получение статистики и отчетов
- Управление кампаниями и объявлениями
- Управление ставками (биддинг)

---

## Подробное описание работы приложения

### 1. Используемые методы API

#### 1.1. API v5 (JSON)

| Метод | Сервис | Описание | Частота вызова |
|-------|--------|----------|----------------|
| `Campaigns.get` | campaigns | Получение списка кампаний с параметрами | 1 раз в сутки |
| `AdGroups.get` | adgroups | Получение групп объявлений по ID кампаний | 1 раз в сутки |
| `Ads.get` | ads | Получение объявлений по ID групп | По необходимости |
| `Keywords.get` | keywords | Получение ключевых фраз по ID групп | 1 раз в сутки |
| `Bids.set` | bids | Установка ставок для ключевых фраз | По запросу менеджера (не чаще 1 раза в час) |

#### 1.2. Reports API

| Тип отчета | Описание | Частота запроса |
|------------|----------|-----------------|
| `CAMPAIGN_PERFORMANCE_REPORT` | Статистика по кампаниям | 1 раз в сутки |
| `CRITERIA_PERFORMANCE_REPORT` | Статистика по ключевым фразам | 1 раз в сутки |

### 4. Обработка ошибок

#### 4.1. Категории ошибок и стратегии обработки

| Категория | Коды ошибок | Стратегия | Действие |
|-----------|-------------|-----------|----------|
| **Авторизация** | 52, 53, 54 | Не повторять | Логирование, уведомление администратора |
| **Лимиты** | 506, 9000 | Ждать и повторить | Ожидание 60 сек, до 3 попыток |
| **Временные** | 1000, 1001, 1002 | Повторить с задержкой | Экспоненциальная задержка, до 3 попыток |
| **Данные** | 8000, 8800 | Не повторять | Логирование, пропуск операции |
| **HTTP 5xx** | 500, 502, 503 | Повторить с задержкой | Экспоненциальная задержка, до 3 попыток |

#### 4.2. Алгоритм повторных попыток

```python
# Экспоненциальная задержка
base_delay = 1.0  # секунд
multiplier = 2.0
max_retries = 3

for attempt in range(max_retries):
    try:
        response = make_request()
        break
    except TemporaryError:
        delay = base_delay * (multiplier ** attempt)
        # Задержки: 1с, 2с, 4с
        time.sleep(delay)
```

#### 4.3. Логирование ошибок

Все ошибки логируются с сохранением:
- Код ошибки
- Текст сообщения
- Время возникновения
- Параметры запроса
- Номер попытки

Пример записи в лог:
```
2024-01-15 03:15:23 ERROR - API Error: [506] Rate limit exceeded -
  Request: campaigns.get, Attempt: 2/3, Retry in: 2.0s
```

### 5. Учет ограничений API

#### 5.1. Rate Limiting (ограничение частоты)

| Ограничение | Значение | Как учитывается |
|-------------|----------|-----------------|
| Запросов в секунду | 5 | Token Bucket алгоритм, интервал 200мс |
| Объектов в запросе | 10000 | Автоматическое разбиение на батчи |
| Баллы операций | По тарифу | Мониторинг через заголовок Units |

**Реализация Rate Limiter:**
```python
class RateLimiter:
    """
    Token Bucket алгоритм.
    Гарантирует не более 5 запросов в секунду.
    """
    max_requests = 5
    window_size = 1.0  # секунда

    def wait_if_needed(self):
        # Проверяем количество запросов за последнюю секунду
        # Если >= 5, ждем до освобождения слота
        pass
```

#### 5.2. Мониторинг баллов (Units)

После каждого запроса программа анализирует заголовок `Units`:
```
Units: 10/20000/30000
       │  │      └─ Лимит баллов в сутки
       │  └─ Использовано баллов
       └─ Баллов за текущий запрос
```

При достижении 80% лимита:
- Логирование предупреждения
- Уведомление администратора

#### 5.3. Обработка Reports API

Особенности работы с отчетами:
1. **Асинхронное формирование** - отчет может формироваться до 10 минут
2. **Интервал опроса** - проверка готовности каждые 10-60 секунд (по заголовку `retryIn`)
3. **Таймаут** - максимальное ожидание 10 минут

```
HTTP 200 - Отчет готов, данные в теле ответа
HTTP 201 - Отчет формируется, повторить через retryIn секунд
HTTP 202 - Отчет в очереди, повторить через retryIn секунд
```

### 6. Дополнительная информация

#### 6.1. Безопасность

- OAuth токен хранится в переменных окружения (не в коде)
- Логи не содержат токены и пароли
- Используется HTTPS для всех запросов

#### 6.2. Масштабируемость

Текущие параметры:
- Количество клиентов: до 10
- Кампаний на клиента: до 100
- Ключевых фраз: до 10000

При увеличении нагрузки:
- Распределение запросов по времени
- Увеличение интервалов между клиентами
- Параллельная обработка (с учетом общего лимита 5 req/sec)

Приложение тестируется в sandbox режиме:
- URL: `https://api-sandbox.direct.yandex.com/json/v5/`
- Отдельный токен для тестового аккаунта
